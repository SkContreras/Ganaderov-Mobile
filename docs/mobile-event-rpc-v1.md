# Paso 7 — piloto RPC de eventos Android

SQLite v3 añade cuerpo inmutable de operación, estado y recibo a event_outbox, además de ID de instalación persistente. Las entradas v2 se conservan en ruta antigua, incluso si se habilita RPC, porque un intento previo puede haber llegado al servidor. Las entradas nuevas RPC nunca recurren a la escritura anterior; si flag desactivado permanecen pendientes. El UUID de operación es distinto del evento y se persiste antes del envío. La RPC recibe actor desde sesión. Confirmaciones válidas se conservan en SQLite, conflictos y rechazos se muestran y no se reintentan automáticamente. Los registros confirmados se descargan por inventario existente; no se muestran en cola de pendientes. Reintentos usan backoff existente y timeout de 20 segundos (no cancela solicitud subyacente). No hay WorkManager ni resolución de conflictos. El flag SYNC_EVENT_RPC_V1=true debe usarse solo con URL y clave de staging, después de instalar y validar backend. Ausente por defecto. No cambia Supabase. Pruebas unitarias añadidas; falta verificar migración real v2, red, permisos y concurrencia. No eliminar SQLite ni cambiar de entorno con cola pendiente; usar instalación de staging separada.
