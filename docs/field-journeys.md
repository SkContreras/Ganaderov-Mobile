# Jornadas móviles (primera fase)

Lee journey_sync_records, crea jornadas de los siete tipos autorizados con selección de activos, registra atención y peso/corrección durante jornada abierta, filtra y consulta progreso e historial. RLS existente, actor autenticado, CAS por updated_at, UUID estable al reintentar creación. No escribe eventos individuales durante atención: la web los materializa al finalizar con ID determinista y actor original. El cierre se hace desde la web porque el backend actual no proporciona una operación atómica de finalización y el trigger de eventos de trabajador exige que el actor sea el usuario autenticado; cerrar desde otro trabajador podría dejar registros parciales. No se modifica backend. Pendientes cierre móvil transaccional, reanudación, agregar animales después de iniciar, actividades personalizadas y offline. Validar con dos cuentas y comparar web tras sincronizar.
