# Paso 14 — protección local Android
Limpieza de cache de inventario al iniciar, cambiar cuenta o cerrar sesión (sin borrar event_outbox). Invalida cache de otro rancho al comprobar membresía remota antes de descargar. Rechaza cache con rol desconocido, conserva TTL anterior 24 h. Generación de consultas evita publicar resultados de consultas reemplazadas, pero consultas simultáneas pueden fallar y deben reintentarse. No bloquea login por fallo de limpieza inicial. Android bloquea tráfico HTTP claro y ya tenía backup deshabilitado. No se introduce SQLCipher ni almacenamiento seguro de tokens; SQLite sigue en sandbox sin cifrado de aplicación. No se garantiza borrado seguro de páginas SQLite/WAL ni revocación offline instantánea. Pendientes cifrado autenticado con gestión de claves, migración conservadora de outbox y aislamiento por entorno, coordinación de sesiones entre isolates, bloqueo de pantalla, pruebas de dispositivo y CI. No modificar Supabase ni borrar pendientes.
