# 16.7 — envío RPC Android en segundo plano
Activación solo staging mediante SYNC_BACKGROUND_V1 y SYNC_EVENT_RPC_V1. WorkManager usa un token de acceso vigente publicado por el proceso principal en flutter_secure_storage, ligado a URL y usuario, sin copiar refresh token. Cuando expira o se borra, pausa; no renueva sesión. Usa HTTP autenticado, máximo 8 operaciones por ejecución, mismo UUID y recibo. SQLite v4 añade lease con expiración 60 s y liberación por titular; foreground y worker comparten. No garantiza exclusión si una solicitud sigue ejecutándose después de expirar lease: idempotencia server protege RPC. Legacy no se envía en headless. Logout elimina credencial antes de signOut; petición ya iniciada puede finalizar, JWT emitido sigue válido hasta expirar, membresía se verifica en servidor. No garantiza cancelación instantánea ni envío después de expirar token, force-stop Android o intervalos exactos. No habilitar hasta pruebas de migración v3, dos conexiones, dispositivo, logout, expiración, RLS y CI. Secure storage contiene una copia del access token (no refresh); no es migración completa de credenciales ni cifrado SQLite.
